## 7–9. Exact ellipsis insertion point (intentional)

**Insertion is GDI layout, not a C# string assignment.**

The in-memory model is never rewritten to contain `"..."`.  
`Graphics.DrawString(..., layoutRect, format)` with

```text
Trimming = StringTrimming.EllipsisCharacter
```

draws an ellipsis **glyph in the raster** when the text does not fit the rectangle.

Factories (shared with invoice/test page):

```403:415:desktop/Sirman.Desktop/NativeWindowsPrintService.cs
private static StringFormat RtlFormat() => new(StringFormatFlags.DirectionRightToLeft | StringFormatFlags.LineLimit)
{
    Alignment = StringAlignment.Near,
    LineAlignment = StringAlignment.Center,
    Trimming = StringTrimming.EllipsisCharacter
};

private static StringFormat LtrFormat() => new(StringFormatFlags.NoWrap | StringFormatFlags.LineLimit)
{
    Alignment = StringAlignment.Near,
    LineAlignment = StringAlignment.Center,
    Trimming = StringTrimming.EllipsisCharacter
};
```

Postal call sites that pass these formats:

| Site | Text | Format | Layout rectangle |
|---|---|---|---|
| L320 | `"فرستنده: " + sender.Addr` | `rtl` (LineLimit + Ellipsis) | width `firstW`, **height 36** |
| L322 | zip via `DrawPostalIdLine` | label `rtl`, value `ltr` **NoWrap + Ellipsis** | **height 16** |
| L327 | tel + person via `DrawPostalIdLine` | same | **height 16** |
| L344 | `"آدرس گیرنده: " + rcv.Addr` | `rtl` | full inner width, **height 36** |
| L346 | recipient zip | id line | **height 16** |
| L348 | recipient tel | id line | **height 16** |
| L352 | `rcv.Name` | `rtl` | **height 18** |
| L365 | `rcv.Note` | `centerRtl` = RtlFormat | badge, width capped |

`DrawPostalIdLine` L375–387:

```text
stored = value                        // still complete
presented = AsLeftToRight(stored)     // still complete + bidi marks
labelRect = right 45% (capped)
valueRect = leftover width, same height 16
DrawString(label, rtl)
DrawString(presented, ltr)            // NoWrap → single line → EllipsisCharacter
```

`TextRenderer`: **not used** on this path.  
C# `Substring` / `Truncate` / `maxLength` on postal fields: **none**.

This is **intentional truncation to fit a fixed rectangle** (`StringTrimming.EllipsisCharacter` + `LineLimit`, and `NoWrap` on LTR values).

## 10. Exact A5 label dimensions used by the renderer

Paper (not disputed; shop proved A5):

```text
NativePrintLayout.ParsePaper("A5")  L61–62
  583 × 827 hundredths of an inch
  ≈ 148 × 210 mm  (ISO A5)

  NativePrintPaper.DocumentDefaultMarginMm(postalLabel) → 10f

  PrintDocument.DefaultPageSettings.Margins = (39,39,39,39)

DrawPostalLabel uses e.MarginBounds (printable area after those margins).
Graphics page unit for PrintDocument is 1/100 inch.
```

Computed **if** `MarginBounds` equals A5 page minus 39+39:

```text
Page:   583 × 827
Bounds: 505 × 749   hundredths   (≈ 128.3 × 190.2 mm)

DrawPostalLabel L277–286  always 2×2, gap = 10 hundredths (≈ 2.54 mm)
  colW = (bounds.Width  - 10) / 2  → ≈ 247.5 hundredths ≈ 62.9 mm
  rowH = (bounds.Height - 10) / 2  → ≈ 369.5 hundredths ≈ 93.9 mm

Inner pad Inflate(-8,-8):
  usable ≈ 231.5 × 353.5 hundredths  (≈ 58.8 × 89.8 mm per card)

Sender address width with logo:
  logoW = min(72, inner.Width * 0.35) = 72 hundredths ≈ 18.3 mm
  firstW ≈ inner.Width - 72 - 8 ≈ 151.5 hundredths ≈ 38.5 mm
  height of address DrawString = 36 hundredths ≈ 9.1 mm
```

Actual `MarginBounds` on a given Windows printer can differ slightly if the installed A5 form or unprintable hardware margins differ. The **2×2 split and the 36/16/18 rect heights are hardcoded** and do not grow with paper.

`ps-postal-count` (1/2/4) exists in Print Center UI and is **not read** by `DrawPostalLabel` or `buildPostalPreviewCards`. Native always draws four cards.

## 12–14. Persian measurement and RTL/LTR

```text
RtlFormat: DirectionRightToLeft | LineLimit | EllipsisCharacter
  used for Persian addresses, name, fragile, zip/tel labels

LtrFormat: NoWrap | LineLimit | EllipsisCharacter
  used for zip/tel VALUES after NativePrintBidi.AsLeftToRight

AsLeftToRight wraps the stored string with U+202A … U+202C.
  Stored zip/tel in the model stay unchanged.
  Presentation string is longer by 2 characters.
  ReverseHyphenated is NOT applied on the print path
  (test documents that "2000-35155" must not become "35155-2000" in AsLeftToRight).
```

Persian measurement caveats (source-level, not a GDI dump):

1. Address `DrawString` uses RTL format, but **height 36** + `LineLimit` stops after ~two 9pt lines, then ellipsis. GDI does not wrap to the rest of the card.
2. `DrawPostalIdLine` measures the Persian **label** with `MeasureString(labelText, labelFont)` **without** the RTL `StringFormat`. Width of `"کدپستی:"` / `"شماره تماس:"` can be wrong; leftover `valueRect` may be tighter than it looks.
3. Zip/tel values are **NoWrap**. A 10-digit code usually fits; longer strings, LRE/PDF marks, or `tel + " " + person` overflow → ellipsis.
4. Sender **person is Persian** but is concatenated onto tel and forced through `AsLeftToRight` + `LtrFormat`. Mixed-direction on one NoWrap line is the highest-risk phone line.
5. Fragile `MeasureBadge` uses `MeasureString(text, font)` without RTL format, then draws with `RtlFormat` + Ellipsis into a width-capped badge.
6. `TextRenderingHint = AntiAlias` (L52). No `StringFormat.GenericTypographic`. Default GDI measure vs draw mismatch is possible (classification C, secondary).

HTML preview: `direction:rtl`, `line-height:1.8`, **no** `text-overflow:ellipsis` on `.postal-box`. Long addresses wrap.

```text
    REJECTED. Model and TryParse keep full strings. No JS/C# "..." write.

B — renderer intentionally truncates
    PRIMARY. RtlFormat/LtrFormat.Trimming = StringTrimming.EllipsisCharacter.
```

## Recommended minimal fix (NOT implemented)

Do **not** touch `NativePrintPaper` / P0.1 form selection.

Postal-only layout in `NativeWindowsPrintService` (do not reuse a changed `RtlFormat` for invoice):

1. Postal `StringFormat`: `Trimming = StringTrimming.None` (or `Word`), drop `NoWrap` on values that must show in full.
2. Let address use remaining card height instead of a 36-hundredths `LineLimit` box (HTML already wraps).
3. Draw sender `person` as a separate RTL line; keep `AsLeftToRight` only on zip/tel digits.
4. Keep 2×2 cards unless product asks to honor `ps-postal-count`.
5. Add a Core/GDI or HTML contract test: long Persian addr + 10-digit zip + tel+person must not rely on EllipsisCharacter.
