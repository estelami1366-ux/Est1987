## Logo pipeline

```text
localStorage['ll']  OR  default data URL  OR  disk://sirman_media/logo.jpg
  → global logoSrc   (Sirman_Final.html ~7507, default ~7574)
  → printPostalNative()
       readPostalLabelData()     ← sender/recipient fields ONLY; no logo
       printEngineBuildPostalLabelModel()
         logoSrc: opt.logoSrc || global logoSrc     (~24841)
  → printEnginePrintNative()
       payload = model + paper/orientation
       host.PrintDocument(JSON.stringify(payload))
  → SirmanHostObject.PrintDocument
  → NativePrintRequest.TryParse
       PostalLabel.LogoSrc = FirstNonEmpty(logoSrc, logoDataUrl, logo)  (NativePrintModels ~293)
  → NativeWindowsPrintService.Submit
       Image? logo = TryAnyLogo(request.PostalLabel?.LogoSrc)   (~39–40)
  → DrawPostalLabel → DrawPostalSenderCard only
       if (logo is not null) { DrawRoundRect; DrawImage; optional BrandEn }
```

`readPostalLabelData` does **not** carry logo. Logo is attached later from the global `logoSrc`. That is intentional and matches invoice native (`printEngineBuildInvoiceModel` also copies global `logoSrc`).

## PART B — orientation (source)

A5 Test Page uses the **same** `PrintPage` prefix: `e.MarginBounds`, no transform, `TextRenderingHint` only. A5 Test **PASS** ⇒ page Landscape/HDC for A5 is **good enough for upright text**.

`DrawPostalLabel` (~277–288):

- Uses **only** `MarginBounds` (same rectangle Test Page used).
- No `RotateTransform` / `TranslateTransform` / `ScaleTransform` / `Matrix` / `PageUnit` assignment (grep empty in this file).
- Splits bounds into a **2×2** grid, gap 10.
- Origin of each card = `bounds.Left/Top` (GDI top-left of the margin box).
- No Y-axis invert, no page-relative vs margin-relative extra conversion.

Postal-specific **text** behavior (not a 180° rotate):

- `PostalRtlWrapFormat` = `StringFormatFlags.DirectionRightToLeft` (also used on Test Page via `RtlFormat`; Test Page upright ⇒ RTL flag is **not** a 180° mechanism).
- Zip/phone drawn LTR on the **left** of the id block; labels RTL on the **right**.
- If logo is null, address starts at `inner.Left` instead of to the right of a logo box — layout **looks** different from HTML preview (which still shows a logo box when `img` loads).

Do **not** invent `RotateTransform`. Do **not** blame the printer: A5 Test is the control.

**Orientation classification:** **source issue** for Postal **layout** (2×2, RTL field packing, logo-null collapsing the sender header). Remaining “upside-down glyphs” would be **unknown** without `P0.5R4_NATIVE_RUNTIME.log` / photo; it is **not** explained by A5 device mapping after the A5 Test PASS.

## Classification

### Logo

**C — image path/resource missing on Windows** (native resolver), with **F** as the package fact (no logo asset in the kit).

Supporting chain: autosave offloads any data URL **> 800** chars to `disk://sirman_media/logo.jpg`; `TryAnyLogo` does not implement `disk://`; BaseDirectory has no `logo.jpg`. Exceptions swallowed ⇒ silent omit.

Not **A** as the designed pipeline (model always copies `logoSrc`).  
**A** only if shop `logoSrc` is literally empty (default assignment exists).  
**B** only if JSON dropped the field despite parse success (unproven).  
**D** possible for a **data:** payload that `Image.FromStream` rejects; default is JPEG (`/9j/`) which GDI+ normally accepts; no shop log.  
**E** weak: failed `DrawImage` would still leave the rounded logo **frame**. Shop reports no logo at all.  
**G:** `TryAnyLogo` returns null for `http:`/`https:`/`file:` by design; `ps.postal.logo` unused.

### Orientation

**source issue** (Postal renderer layout vs Test Page), **not** A5 driver.  
Runtime 180° of glyphs: **unknown** (no new HDC log/photo in this packet).
